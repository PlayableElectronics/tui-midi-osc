# Index architecture

The first slice is deliberately two-process and sequencing-only. Rust owns project files, the Ratatui UI, supervision, OSC transport, and the native MIDI boundary. A headless `sclang` owns staged/live managed pattern environments, a real `Pbind` event stream, its clock, and normalized event production. The stream is consumed as Events rather than played through the default Event prototype, so no synth or audio server is started. Quitting the UI stops the supervised child so the prototype cannot leave an unintended `sclang` behind.

The OSC protocol is versioned under `/index/v1`. Rust sends `/hello`, `/project/sync(request_id, tempo, name, degrees_csv, durations_csv, velocities_csv, gate, channel, destination)`, `/pattern/set(request_id, revision, name, degrees_csv, durations_csv, velocities_csv, gate, channel, destination)`, and `/pattern/commit(request_id, revision, mode)` where mode is `now` or `bar`. SC replies `/ready(1, sc_monotonic_seconds)`, `/project/sync_ack(request_id, revision, name)`, `/pattern/staged(request_id, revision)`, `/pattern/committed(request_id, revision, mode, beat)`, `/state(playing)`, `/event/midi(timestamp, kind, note, velocity, channel, destination)`, and `/error(message)`. Pattern arrays remain validated CSV strings in v1 because the installed SuperCollider OSC API has less predictable nested-array coercion across versions; request IDs and revisions make each mutation correlated. Event timestamps are monotonic seconds from the SC process start; the current prototype forwards events immediately and does not claim sample-accurate native MIDI scheduling.

Future work, not implemented in this slice: reusable sequencing tools/agents; tracker and indexed views over managed SC objects; arrangements and scenes; modulation matrices for event/control messages; device profiles; native SC livecoding UX; and NerdSEQ, Dyaxis, and custom OSC-node integration. Clock sources should later implement `Internal`, `MIDI input`, `NerdSEQ`, and `OSC` behind a common interface.
